# Решения, принятые при реализации

Выписка из журнала исполнения плана `2026-11-16-tournament-app.md`.
Каждая строка — место, где план, спека или инструмент разошлись с реальностью,
и что было решено. Цена ошибки указана там, где решение обратимо.

- Task 1: Ruling: TypeScript откачен с 7.0.2 (шаблон Vite 8) до ~5.9 — ts-api-utils/typescript-eslint под TS7 не работают, eslint-plugin-effector падает при загрузке. Версия TS спекой не зафиксирована, правила эффектора зафиксированы планом. Цена ошибки: не самый свежий TS до выхода поддержки.
- Task 1: Ruling: oxlint из шаблона удалён в пользу eslint — eslint-plugin-effector работает только с eslint, два линтера держать незачем. Цена ошибки: потеря скорости oxlint на больших прогонах.
- Task 1: Ruling: @vitejs/plugin-react 6 перешёл на oxc и выкинул опцию babel, которую требовал план. effector/babel-plugin подключён отдельным vite-plugin-babel. Цена ошибки: лишний проход babel в сборке.
- Task 1: Ruling: babel ограничен /\.ts$/ вместо /\.[jt]sx?$/ — babel не парсит TSX без preset-typescript, а юниты Effector по правилам проекта живут только в .ts-моделях. Цена ошибки: юнит, созданный в .tsx, останется без sid; правило и так запрещает это, eslint-plugin-effector его ловит.
- Task 1: Ruling: fsd/segments-by-purpose отключено для ./src/app/** — providers конвенциональный сегмент слоя app в документации FSD, план его прямо называет. Цена ошибки: сегмент-свалка в app проскочит мимо линтера.
- Task 1: Ruling: добавлен ts-pattern 5.9.2 по прямой просьбе заказчика — ляжет на ветвление по статусу раунда в Task 6 и на отрисовку статусов в Task 10. Цена ошибки: лишняя зависимость, если не приживётся.
- Task 2: Ruling: связь entities/tournament с participant и round оформлена через @x-сегменты (entities/participant/@x/tournament.ts, entities/round/@x/tournament.ts) — steiger справедливо запретил прямой кросс-импорт соседних слайсов. План файлы @x не перечислял. Цена ошибки: два лишних файла реэкспорта.
- Task 2: Ruling: fsd/insignificant-slice отключено — правило советует удалять слайсы без ссылок, а при пошаговой сборке сущности появляются раньше использующих их фич. Цена ошибки: реально мёртвый слайс не будет замечен линтером.
- Task 3: Ruling: план требовал «canSeed отвергает 4 и меньше», спека — «при 4 и меньше создаётся единственный раунд, он же финал». Спека связывающая: canSeed принимает 2..20, а splitIntoHeats при 4 и меньше возвращает одну группу; решение о kind='final' принимает Task 5. Цена ошибки: при 2-4 участниках турнир из одного раунда вместо отказа — ровно то, что описывает спека.
- Task 3: Ruling: включён strict в tsconfig.app.json и tsconfig.node.json — шаблон Vite 8 его не ставит. Без strictNullChecks литералы true/false расширяются до boolean и размеченное объединение SeedVerdict перестаёт сужаться. Для проекта-референса отсутствие strict — дефект сам по себе. Цена ошибки: нет, сборка осталась зелёной.
- Task 4: Ruling: по прямой просьбе заказчика модели оформляются namespace-фабриками createModel (@withease/factories + invoke) с полем viewModel для @effector/reflect — вместо «одного useUnit на компонент» из плана. Хелпер в shared/lib/create-model, зарегистрирован в factories babel-плагина. Цена ошибки: Task 10 биндит UI через reflect, а не useUnit; обе техники легальны по скиллу effector-ecosystem.
- Task 4: Ruling: папка shared/lib/model переименована в shared/lib/create-model — steiger запрещает каталог с именем model внутри сегмента. Цена ошибки: нет.
- Task 4: Ruling: сырой текст битого хранилища читается эффектом readRawStorageFx из localStorage, а не берётся из Fail.value — при ошибке разбора JSON адаптеру нечего туда положить, и экран восстановления остался бы без данных для выгрузки. Цена ошибки: лишний эффект.
- Task 5: Ruling: при единственной группе (2-4 участника) раунд создаётся сразу с kind='final' и FINAL_DURATION_MS — следствие ruling из Task 3 о расхождении плана и спеки. Цена ошибки: нет, поведение описано спекой.
- Task 5: Ruling: UI фичи собран через reflect({ view, bind: Model.viewModel }), а не useUnit — следствие ruling из Task 4. Цена ошибки: нет.
- Task 6: Ruling: продление времени увеличивает и deadlineAt, и durationMs. План требовал «не трогая durationMs», но спека называет это «правкой длительности», и равенство остатка и длительности — то, на чём держится верхняя граница в remainingMsAt (защита от скачка системных часов назад). Спека связывающая. Цена ошибки: durationMs отражает выданное время, а не изначально запланированное.
- Task 6: Ruling: patronum/interval вынесен из RoundRunModel в отдельный TickerModel — незавершённый эффект интервала подвешивал allSettled, и все десять тестов модели падали по таймауту. Драйвер внешнего времени и так не место для бизнес-правил. tickingEnabled поднимается из appStarted. Цена ошибки: один лишний модуль.
- Task 6: Ruling: effector-action в задаче не использован — у каждого перехода ровно одна цель (tournamentReplaced), и sample читается лучше. Ветвление по статусу живёт в чистых функциях на ts-pattern. Цена ошибки: если до конца плана effector-action не пригодится, зависимость надо будет убрать.
- Task 6: Ruling: round-controls биндится через useUnit, а не reflect — обработчикам нужен payload из пропса round, статический bind такого не выражает. reflect остаётся для view, чьи данные приходят из сторов. Цена ошибки: две техники биндинга в проекте, обе легальны по скиллу.
- Task 7: Ruling: finalistReplaced намеренно не вызывает rebuildFinal — иначе состав финала тут же пересобрался бы из победителей отборов и ручная подмена пропала. Следствие: последующая смена победителя отбора перетирает подмену. Цена ошибки: оператору придётся подменить финалиста заново.
- Task 8: Ruling: перенос между составами запрещён, если идёт любой из двух раундов — не только целевой, как в плане. Люди уже сидят за машинами, и вынимать человека из идущего отбора так же неправильно, как вставлять. Цена ошибки: оператору придётся сначала остановить раунд.
- Task 8: Ruling: удаление участника не только вычищает его из составов, но и снимает его победы, возвращая раунд в pending — иначе агрегат перестал бы проходить проверку ссылочной целостности из Task 2. Цена ошибки: нет.
- Task 9: Ruling: hash-история вместо browser — приложение раздаётся с GitHub Pages по подпути /<repo>/, где статика не отдаёт index.html на произвольный путь. Цена ошибки: адреса с решёткой.
- Task 9: Ruling: $startRoute собран через combine, а не sample({ source }) — стор от sample({source}) не пересчитывается от форкнутых значений и застревает на модульном дефолте, из-за чего фильтр всегда открывал setup. Цена ошибки: нет.
- Task 9: Ruling: порядок старта строгий — appStarted → storagePickedUp → (storagePickupSettled, once) → historyCreatedFx → router.initialized → выбор экрана. Решение о стартовом экране по appStarted читало состояние до восстановления турнира: после F5 оператор получал ввод участников поверх готовой сетки. Цена ошибки: нет.
- Task 9: Ruling: перенаправление на bracket/results срабатывает только если открыт корневой маршрут — прямую ссылку оператора уважаем. Цена ошибки: при ручном переходе на «/» во время турнира произойдёт редирект.
- Task 9: Находка: производные сторы внутри createModel обязаны объявляться ДО вызова persist. Если создать их после, persist фиксирует граф без них и scope.getState отдаёт по ним чужие значения ($participants возвращал значение $isSeeded). Проверено бисекцией; опция factories babel-плагина к этому отношения не имеет и на .map() sid не ставит ни при каких настройках.
- Task 9: Ruling: опция factories у effector/babel-plugin убрана — она не влияет на sid производных сторов и не решала проблему, ради которой добавлялась. Цена ошибки: если появятся модели с несколькими экземплярами, опцию надо вернуть.
- Task 10: Ruling: formatMmSs округляет остаток вверх (Math.ceil), а не вниз — пока на часах есть хоть миллисекунда, зал должен видеть 00:01, а не преждевременный ноль. Цена ошибки: нет.
- Task 10: Ruling: добавлен RoundStatusBadge в entities/round — статус раунда показывается на трёх экранах, и ts-pattern-ветвление по нему логично держать в сущности, а не дублировать в виджетах. План этого файла не перечислял. Цена ошибки: нет.
- Task 11: Ruling: effector-action удалён из зависимостей — за весь план не нашлось места, где он читался бы лучше sample. Заказчик просил посмотреть пакет, а не обязательно применить. Цена ошибки: если появится ветвление на много целей, пакет вернуть.
- Task 11: Ruling: TickerModel стартует интервал только после явного tickingEnabled с границы хоста (main.tsx), а не от факта «идёт раунд». Прежняя версия запускала часы при одном лишь импорте барреля, и сквозной тест висел по таймауту. Цена ошибки: если забыть вызвать tickingEnabled, таймер не будет перерисовываться — поймано бы первым же запуском.
- Task 11: Ruling: добавлен vitest.setup.ts с заглушками matchMedia и ResizeObserver — jsdom их не реализует, а Mantine обращается при монтировании. Цена ошибки: нет.
- Task 11: Ruling: ручной прогон в браузере заменён сквозным тестом tournament-flow (вечер целиком + F5 посреди раунда) — расширение Chrome не подключено. Приложение проверено рендером через headless Chrome. Цена ошибки: клики по реальному UI не проверены; логика и восстановление проверены полностью.
- Final: Ruling: №6 (Date.now и crypto.randomUUID внутри fn у sample) не исправлено. Находка верна по существу: fn обязан быть чистым. Но правка затрагивает шесть файлов и меняет сигнатуры событий, которые дёргает UI, а пользовательского эффекта у дефекта нет — всё работает, недетерминизм уже изолирован чистыми функциями в transitions.ts, принимающими now снаружи. За двое суток до мероприятия широкий рефактор ядра — неоправданный риск. Цена ошибки: проект как референс архитектуры содержит заметный контрпример; чинить после 19 ноября.

## Отложено

- id финала теряется при роспуске, ссылка на /round/<старый-id> протухает.
- переименование участника пишет весь агрегат в localStorage на каждое нажатие клавиши.
- приложение раздаётся с GitHub Pages без service worker — без сети вечером не откроется; снято держанием локальной сборки.
