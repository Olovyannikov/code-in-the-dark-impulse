# Дизайн: приложение турнирной сетки

**Дата:** 16 ноября 2026
**Статус:** согласован

## Зачем

Вечер 19 ноября ведут три человека, и сейчас сетка живёт в голове ведущего и на бумаге. Инструмент должен снять с него учёт: кто в каком отборе, сколько осталось времени, кто прошёл дальше. Ошибка в четверг стоит дорого — пересаживать четвёрку обратно уже не получится.

Приложение запускается на ноутбуке оператора. **В зал оно не выводится** — зрители смотрят на мониторы участников.

## Цели

- Ввести участников списком и перемешать их случайно
- Построить сетку: отборы по 4 человека → финал победителей
- Запустить раунд с честным таймером, который не врёт при сворачивании вкладки
- Отметить победителя раунда и автоматически перенести его в финал
- Исправить любую ошибку оператора, не сбрасывая турнир
- Пережить случайный `F5` без потери турнира
- Служить референсом архитектуры Effector после мероприятия

## Не-цели

- Голосование с телефонов зала — остаётся в Mentimeter
- Протокол мест и чисел голосов — остаётся на бумаге у ведущего
- Проекция на второй экран
- Бэкенд, аккаунты, мультипользовательность
- Хранение работ участников
- Мобильная вёрстка

## Анти-цели

- Приложение, которое в четверг подвело и пришлось вести на бумаге
- Таймер, отсчитавший не те минуты из-за троттлинга фоновой вкладки
- Библиотеки в стеке «для галочки» вместо решения задач

## Решения по стеку

| Выбор | Решение | Почему |
|---|---|---|
| Сборка | Vite + React 19 + TypeScript | — |
| UI | Mantine 9 | решено заказчиком |
| Логика | Effector 23 + `effector-react` | решено заказчиком |
| Операторы | `patronum` | `interval`, `reset`, `condition`, `status` |
| Ветвление | `effector-action` | жизненный цикл раунда ветвится сильно |
| Хранение | `effector-storage/local` | данные измеряются килобайтами |
| Валидация | `@withease/contracts` | localStorage — недоверенный источник |
| Роутинг | `atomic-router` | экраны — часть Effector-архитектуры |
| Тесты | Vitest + `fork`/`allSettled` | — |
| Линт | `eslint-plugin-effector`, Steiger | — |

**`effector-refetch` не используется.** У приложения нет сети: `retry`, `cache`, `concurrency` и `timeout` нечего применять к чтению localStorage.

**IndexedDB не используется.** Турнир — это килобайты, а готового адаптера в `effector-storage` 8 нет.

## Доменная модель

```ts
type Participant = { id: string; name: string };

type RoundKind = 'heat' | 'final';
type RoundStatus = 'pending' | 'running' | 'paused' | 'timeup' | 'finished';

type Round = {
  id: string;
  kind: RoundKind;
  order: number;
  participantIds: string[];   // 2..5
  status: RoundStatus;
  winnerId: string | null;
  durationMs: number;
  deadlineAt: number | null;  // epoch ms, пока running
  remainingMs: number | null; // пока paused или timeup
};

type Tournament = {
  schemaVersion: number;
  participants: Participant[];
  rounds: Round[];
  seededAt: number | null;
};
```

Чемпион — производное: победитель раунда с `kind: 'final'`. Отдельным полем не хранится, чтобы не рассинхронизировалось.

## Жеребьёвка и форма сетки

Неполные отборы разрешены — это норма вечера, а не ошибка.

- Участники перемешиваются, затем распределяются по отборам **равномерно**: 14 человек дают 4 / 4 / 3 / 3, а не 4 / 4 / 4 / 2
- Число отборов — `ceil(N / 4)`, минимальный размер отбора — 2
- Финал собирается из победителей всех отборов, когда все отборы завершены
- Минимум для турнира — 5 участников (два отбора). При 4 и меньше создаётся единственный раунд, он же финал
- **Максимум 5 отборов (20 участников).** Больше — приложение отказывается от жеребьёвки и объясняет, что нужен дополнительный круг, который не поддерживается

## Как работает таймер

Хранится **`deadlineAt` как абсолютный timestamp**, а не счётчик. `patronum/interval` тикает раз в секунду только для перерисовки; остаток всегда вычисляется как `deadlineAt - Date.now()`.

Браузер троттлит `setInterval` в фоновой вкладке, и счётчик-накопитель отстал бы на минуты за десятиминутный раунд. Для активности, где десять минут — это весь смысл, это критично.

При паузе `deadlineAt` превращается в `remainingMs`, при снятии паузы — обратно.

**Таймер приложения — источник истины.** Таймкипер смотрит в ноутбук оператора и объявляет отсечки голосом. Зальный таймер, если он есть, дублирует и расхождение в секунды неважно.

Длительность правится **до старта** раунда (сценарий «режем отборы до 8 минут») и **во время бега** кнопкой «+1/+2 минуты» (сценарий «участник потерял минуты из-за зависшего редактора»).

Дойдя до нуля, раунд переходит в `timeup` и ждёт отметки победителя. Звук и мигание — на усмотрение разработчика.

## Редактируемость

Оператор работает в прямом эфире и ошибается. Любое состояние обратимо:

- Сменить победителя завершённого раунда. Если финал уже собран — он пересобирается, а ранее отмеченный победитель финала сбрасывается
- Вернуть завершённый раунд в `pending` (сценарий переигровки на запасном макете)
- Поправить состав отбора вручную после жеребьёвки: добавить опоздавшего, убрать неявившегося, перенести человека между отборами
- Подменить финалиста, если победитель отказался от финала
- Сброс всего турнира — с подтверждением

Ограничение остаётся одно: раунд нельзя закрыть без победителя.

## Повреждённые данные

В данных хранится `schemaVersion`. При провале контракта или несовпадении версии приложение не начинает молча пустой турнир, а показывает экран «данные повреждены» с выбором: начать заново или выгрузить сырой JSON.

Синхронизация между вкладками включена: вторая случайно открытая вкладка не разводит две копии турнира.

## Структура (FSD)

```txt
src/
  app/
    entrypoint/      main.tsx, fork(), Provider
    providers/       MantineProvider, RouterProvider
    model/           app.model.ts — appStarted, pickup хранилища, старт роутера
    routes/          router.ts, history
    styles/

  pages/
    setup/           ввод участников и жеребьёвка
    bracket/         обзор сетки, вход в раунд
    round/           проведение раунда
    results/         чемпион и список победителей

  widgets/
    bracket-board/   визуализация сетки целиком
    round-runner/    композиция таймера, состава и выбора победителя

  features/
    participants-manage/    добавить, удалить, переименовать, вставить списком
    tournament-seed/        жеребьёвка
    round-run/              старт, пауза, досрочный стоп, правка времени
    round-winner-pick/      отметить и переотметить победителя
    round-roster-edit/      правка состава раунда
    tournament-reset/       обнулить турнир

  entities/
    participant/     тип, контракт, чип участника
    round/           тип, контракт, чистые правила, карточка раунда
    tournament/      агрегат, персист, производные сетки

  shared/
    lib/shuffle      перемешивание с инъекцией источника случайности
    lib/time         форматирование mm:ss
    config/          длительности раундов, размер группы
    routes/          объявления путей
    ui/              мелкие обёртки над Mantine
```

Слой `app` владеет стартом: один `appStarted`, из него поднимается хранилище, запускается роутер и открывается начальный экран.

## Обязательное тестовое покрытие

- Жеребьёвка: равномерность распределения, границы 5 и 20, детерминированность при подменённом источнике случайности
- Арифметика таймера: пауза и снятие, добавление времени, переход в `timeup`, устойчивость к скачку `Date.now()`
- Перенос победителей в финал и пересборка финала при смене победителя отбора
- Восстановление из localStorage, включая битые данные и чужую `schemaVersion`
