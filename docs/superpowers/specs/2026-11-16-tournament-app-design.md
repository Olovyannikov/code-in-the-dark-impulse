# Дизайн: приложение турнирной сетки

**Дата:** 16 ноября 2026
**Статус:** на согласовании

## Зачем

Вечер 19 ноября ведут три человека, и сейчас сетка живёт в голове ведущего и на бумаге. Инструмент должен снять с него учёт: кто в каком отборе, сколько осталось времени, кто прошёл дальше. Ошибка в четверг стоит дорого — пересаживать четвёрку обратно уже не получится.

Приложение запускается на ноутбуке оператора. **В зал оно не выводится** — зрители смотрят на мониторы участников, а таймер залу показывают отдельно, как описано в регламенте.

## Цели

- Ввести участников списком и перемешать их случайно, вслух и наглядно
- Построить сетку: 4 отбора по 4 человека → финал четырёх победителей
- Запустить раунд с честным таймером, который не врёт при сворачивании вкладки
- Отметить победителя раунда и автоматически перенести его в финал
- Пережить случайный `F5` без потери турнира
- Служить референсом архитектуры Effector после мероприятия

## Не-цели

- Голосование с телефонов зала — остаётся в Mentimeter
- Проекция на второй экран — явно отклонена
- Бэкенд, аккаунты, мультипользовательность
- Хранение самих работ участников
- Мобильная вёрстка: инструмент для ноутбука оператора

## Анти-цели

Провалом считается:

- Приложение, которое в четверг подвело и пришлось вести на бумаге
- Таймер, отсчитавший не те минуты из-за троттлинга фоновой вкладки
- Архитектура, в которую зашили библиотеки «для галочки» вместо решения задач

## Решения по стеку

| Выбор | Решение | Почему |
|---|---|---|
| Сборка | Vite + React 19 + TypeScript | — |
| UI | Mantine 9 | решено заказчиком |
| Логика | Effector 23 + `effector-react` | решено заказчиком |
| Операторы | `patronum` | `interval` для тика, `reset`, `condition`, `status` |
| Ветвление | `effector-action` | жизненный цикл раунда ветвится на 5+ переходов |
| Хранение | `effector-storage/local` | данные измеряются килобайтами |
| Валидация | `@withease/contracts` | localStorage — недоверенный источник |
| Роутинг | `atomic-router` | экраны — часть Effector-архитектуры, а не `useState` |
| Тесты | Vitest + `fork`/`allSettled` | — |
| Линт | `eslint-plugin-effector`, Steiger | — |

**`effector-refetch` не используется.** У приложения нет сети: `retry`, `cache`, `concurrency` и `timeout` нечего применять к чтению localStorage. Добавление библиотеки сюда было бы декоративным.

**IndexedDB не используется.** Весь турнир — 16 имён, 5 раундов и протокол голосов. `localStorage` покрывает это с запасом, а у `effector-storage` 8 нет готового IndexedDB-адаптера: его пришлось бы строить поверх `async-storage` руками, без выигрыша.

## Доменная модель

```ts
type Participant = { id: string; name: string };

type RoundKind = 'heat' | 'final';
type RoundStatus = 'pending' | 'running' | 'paused' | 'finished';

type Round = {
  id: string;
  kind: RoundKind;
  order: number;
  participantIds: string[];   // до 4
  status: RoundStatus;
  winnerId: string | null;
  durationMs: number;         // 10 мин отбор, 15 финал
  deadlineAt: number | null;  // epoch ms, пока running
  remainingMs: number | null; // epoch-независимый остаток, пока paused
};

type Tournament = {
  participants: Participant[];
  rounds: Round[];
  seededAt: number | null;
};
```

Чемпион — производное: победитель раунда с `kind: 'final'`. Отдельным полем не хранится, чтобы не рассинхронизировалось.

## Как работает таймер

Хранится **`deadlineAt` как абсолютный timestamp**, а не счётчик. `patronum/interval` тикает раз в секунду только для перерисовки; остаток всегда вычисляется как `deadlineAt - Date.now()`.

Это принципиально: браузер троттлит `setInterval` в фоновой вкладке до раза в секунду и реже, и счётчик-накопитель отстал бы на минуты за десятиминутный раунд. При паузе `deadlineAt` превращается в `remainingMs`, при снятии паузы — обратно.

## Структура (FSD)

```txt
src/
  app/
    entrypoint/      main.tsx, fork(), Provider
    providers/       MantineProvider, RouterProvider
    model/           app.model.ts — appStarted, pickup хранилища, старт роутера
    routes/          router.ts, history
    styles/

  pages/
    setup/           ввод участников и жеребьёвка
    bracket/         обзор сетки, вход в раунд
    round/           проведение раунда
    results/         чемпион и протокол

  widgets/
    bracket-board/   визуализация сетки целиком
    round-runner/    композиция таймера, состава и выбора победителя

  features/
    participants-manage/    добавить, удалить, переименовать, вставить списком
    tournament-seed/        жеребьёвка
    round-run/              старт, пауза, досрочный стоп
    round-winner-pick/      отметить победителя
    tournament-reset/       обнулить турнир

  entities/
    participant/     тип, контракт, чип участника
    round/           тип, контракт, чистые правила, карточка раунда
    tournament/      агрегат, персист, производные сетки

  shared/
    lib/shuffle      перемешивание с инъекцией источника случайности
    lib/time         форматирование mm:ss
    config/          длительности раундов, размер группы
    routes/          объявления путей
    ui/              мелкие обёртки над Mantine
```

Слой `app` владеет стартом: один `appStarted`, из него поднимается хранилище, запускается роутер и открывается начальный экран.

## Правила, которые должны быть в коде, а не в голове

- Жеребьёвка возможна только при 8+ участниках и кратности 4 — иначе последний отбор вырожденный
- Победитель отбора попадает в финал в порядке номера отбора
- Финал создаётся только когда все отборы завершены
- Раунд нельзя запустить дважды и нельзя завершить без победителя
- Сброс турнира требует подтверждения

## Что оставлено на усмотрение разработчика

- Конкретная раскладка экранов и выбор компонентов Mantine
- Форма визуализации сетки
- Оформление в палитре «Импульс 2026» — желательно, но не блокирует
- Стратегия идентификаторов (`crypto.randomUUID`)
- Глубина тестового покрытия сверх обязательного минимума: жеребьёвка, арифметика таймера, перенос победителя в финал
