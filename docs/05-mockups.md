# Макеты

## Где они лежат

`mockups/<раунд>/` — `design.html` (эталон, из него генерируется образец),
`reference.png` (то, что видит участник), `instructions.txt`, `assets/fonts/`.

Бандлы участников собираются из них: `./editor/build-all.sh`.
В CI те же бандлы уезжают на GitHub Pages в `/editor/<раунд>/`.

Перегенерировать образец после правки `design.html`:

```sh
cd mockups/round-03 && "/Applications/Google Chrome.app/Contents/MacOS/Google Chrome" \
  --headless --disable-gpu --hide-scrollbars --screenshot=reference.png \
  --window-size=1920,1080 --virtual-time-budget=6000 "file://$PWD/design.html"
```

## Сколько нужно

**Шесть.** Пять играются (четыре отбора + финал), шестой лежит запасным на случай, если макет окажется неподъёмным или раунд придётся переиграть.

Повторять макет между раундами нельзя: зал уже видел четыре решения, а участники следующего отбора сидели в зале и всё запомнили.

## Требования

Макет для code-in-the-dark — это не «красивый дизайн», а **задача, решаемая вслепую за 10 минут**. Критерии:

- **Одна экранная страница.** Никакого скролла на три экрана
- **Крупная читаемая структура**: хедер, большой заголовок, пара блоков. Если структура видна с четырёх метров — хорошо
- **2–4 цвета.** Градиенты и тени участник вслепую не повторит
- **Максимум 2 шрифтовых стиля.** Жирный заголовок и обычный текст
- **Узнаваемый силуэт.** Зал должен уметь сравнить работу с образцом за три секунды
- **Без сеток из 12 одинаковых карточек.** Это проверка усидчивости, а не вёрстки
- **Без фотоколлажей.** Картинки — только те, что лежат в бандле

Хорошая проверка: сверстай макет сам за 10 минут, не глядя на результат. Если не успел — режь.

Сложность по раундам стоит наращивать: первый отбор самый простой, финал — самый интересный.

## Что брать за основу

- Лендинги продуктов с крупной типографикой
- Обложки и постеры мероприятий
- Страницы из гайда «Импульс 2026» — см. [brand/README.md](../brand/README.md). Страница «Макеты» в файле Figma содержит готовые баннеры в фирменном стиле: чёрный фон, циановый акцент, крупный ALS Hauss. Это попадает в тему вечера и выглядит на экране эффектно

## Бандл раунда

Каждому участнику на флешке лежит папка:

```
round-N/
  index.html          редактор, открывается первым
  assets/
    reference.png     скриншот-образец, который надо повторить
    <картинки>        всё, что используется в макете
    <шрифты>          если макет не на системных шрифтах
  instructions.txt    что в ассетах, куда сохранять результат
```

Редактор берётся из [codeinthedark/editor](https://github.com/codeinthedark/editor). Он блокирует превью и работает в полноэкранном режиме.

Образец `reference.png` отдаём **в том же разрешении, в каком участник будет смотреть** — иначе человек вслепую подгоняет размеры под чужой масштаб.

## Ловушка с путями к ассетам

Результат участника показывается в iframe по адресу `assets/result.html`, поэтому
относительные пути в его коде считаются **от папки `assets`, а не от корня бандла**.

Правильно:

```css
src: url('./fonts/ALSHauss-Medium.woff2');
```

Неправильно — файл не найдётся, и участник потеряет раунд:

```css
src: url('assets/fonts/ALSHauss-Medium.woff2');
```

Это написано в `instructions.txt` каждого бандла отдельным блоком. Проверь, что
блок на месте, прежде чем раскладывать флешки.

## Чего делать нельзя

Класть в ассеты HTML или CSS исходники макета. Участник обязан написать разметку с нуля, а соблазн подсмотреть убивает смысл.
